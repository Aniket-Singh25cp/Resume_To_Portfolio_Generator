# AI-Assisted Resume Portfolio Generator

A framework-free student project that reads one `resume.txt`, sends the cleaned text to Gemini from Python, receives structured JSON, and generates a local `portfolio.html` using a separate HTML template and CSS file.

The design layer adds four selectable visual systems while preserving the bootcamp's required resume-to-JSON-to-HTML pipeline.

## What this project satisfies

The bootcamp brief requires the application to read `resume.txt`, clean it, call Gemini, request valid JSON, parse that JSON into Python data, generate `portfolio.html` automatically from a separate template/CSS file, omit empty sections, keep the API key out of source control, and handle missing/invalid inputs safely. It also requires a README, `.gitignore`, `.env.example`, testing evidence and an AI usage log.

This implementation keeps those requirements and adds theme previewing, project filtering, scroll-synced navigation, CSS-generated hero art and an optional `photo.jpg` hero slot.

`portfolio.html` is generated by the program and is ignored by Git so generated output does not accidentally become a source-of-truth file.

## Setup

1. Install Python 3.10+.
2. Create a virtual environment if desired.
3. Install dependencies:

```bash
pip install -r requirements.txt
```

4. Copy `.env.example` to `.env`.
5. Put your Gemini API key in `GEMINI_API_KEY`.
6. Set `GEMINI_MODEL` to the model approved by your instructor.
7. Put the source resume in `resume.txt`.

The Gemini SDK can read `GEMINI_API_KEY` from the environment; this project explicitly loads `.env` for local development and never embeds a real key in source code.

## Run

```bash
python main.py
```

A successful run creates `portfolio.html`. Open that file in a browser.

For a local deterministic smoke test that does not call Gemini:

```bash
python main.py --mock
```

Mock mode is only for testing the renderer and interaction features. The normal project workflow remains Gemini-powered.

## Input handling and safety

- Missing `resume.txt` → clear error and safe stop.
- Empty/very short resume → useful validation error.
- Whitespace is normalized before the prompt is sent.
- API failures are caught and reported instead of crashing with a traceback.
- Gemini JSON is parsed with `json.loads`; no `eval` or executable interpretation is used.
- Markdown code fences around JSON are stripped only as a recovery step.
- Unexpected or incomplete JSON fields are normalized to empty strings/lists.
- HTML content is escaped before insertion.
- External links are accepted only for `http(s)`, `mailto`, `tel` and fragment URLs.
- The Gemini API key is never sent to browser-side JavaScript.

## Prompt design

The prompt in `main.py` deliberately repeats the key grounding constraints from the brief:

1. Use only information explicitly present in the resume.
2. Do not invent skills, experience, projects, achievements, companies, dates, education, links, job titles, metrics or availability.
3. Use empty strings/arrays when information is absent.
4. Keep the professional summary concise and factual.
5. Return JSON only.
6. Follow the predefined JSON schema.

Structured output is also requested from the Gemini SDK using an explicit JSON schema. The prompt is not a replacement for verification: Gemini output is still a draft and every claim should be checked against the original resume before submission.

## JSON shape

The generator asks Gemini for:

```text
name
headline
summary
skills[]
education[]
  degree, institution, dates, details
experience[]
  role, company, dates, details[]
projects[]
  title, description, technologies[], link
achievements[]
contact
  email, phone, linkedin, github, links[]
availability
```

Missing information is represented as empty strings or arrays. The renderer checks these values before creating each section, so empty sections do not leave blank headings or large gaps.

## Theme system

There are four complete visual systems, not just color presets:

| Theme | Layout / typography | Intended feel |
|---|---|---|
| **Vivid Landing** | White base, alternating tinted section bands, oversized sans display type, chips, timeline and project cards | Default, energetic personal landing page |
| **Bold Studio** | Split-screen color blocks, sidebar-like content column, oversized display type, hard borders and high contrast | Designer / artist / creative work |
| **Editorial Minimal** | Full-bleed hero art, lowercase serif navigation, serif + italic pairing, large negative space | Writer / editor / researcher / image-led work |
| **Dark Portfolio** | Near-black base, mono type, grid-like hero art and saturated accent | Developer / engineer / technical portfolio |

### Choosing a theme

Manual selection wins when `THEME` is set in `.env`:

```env
THEME=bold
```

Allowed values are `vivid`, `bold`, `editorial`, and `dark`.

If `THEME` is empty or invalid, `main.py` infers a theme from the generated headline, skills and summary:

- Design / artist / illustrator / photographer / creative language → **Bold Studio**
- Developer / engineer / software / backend / frontend / data engineering / DevOps language → **Dark Portfolio**
- Writer / editor / researcher / architect / journalist / author language → **Editorial Minimal**
- Otherwise → **Vivid Landing**

The inference is presentation-only. It does not add content to the portfolio.

### Live theme preview

The generated page includes a small floating theme switcher. It changes the root `data-theme` attribute with vanilla JavaScript and stores the visitor's selection in `localStorage`. No framework, bundler or build step is required.

The saved preview choice is a browser-side presentation preference; it does not modify the resume data or generated source.

### Adding a new theme

The cleanest extension path is to add one new root theme selector in `style.css`:

```css
html[data-theme="new-theme"] {
  --bg: ...;
  --surface: ...;
  --text: ...;
  --accent: ...;
  --display: ...;
}
```

Then add layout rules under `html[data-theme="new-theme"] ...` for the hero, navigation, section components and responsive behavior. Finally:

1. Add the name to `ALLOWED_THEMES` in `main.py`.
2. Add a button with `data-theme-option="new-theme"` to `template.html`.
3. If it should be automatically inferred, add a narrowly scoped keyword rule in `infer_theme()`.
4. Update this README's theme table.
5. Run `python main.py --mock` and test every populated/empty section.

Keep the content model unchanged unless a new data field is genuinely required by the project brief.

## Hero visual system

The input is plain text, so the project does not require a photograph. When `photo.jpg` exists beside `main.py`, it is used as the hero image. When it does not exist, the page renders CSS-generated visual art instead: layered gradients, circles, geometric forms and line patterns change with the selected theme.

There is no broken-image icon and no reserved empty photo box when `photo.jpg` is absent.

## Interactive UX

- **Theme switcher:** previews all four visual systems live.
- **Project tag filter:** filters project cards by the technologies returned by Gemini.
- **Scroll-synced navigation:** the visible section updates the active nav underline.
- **Availability / role badge:** rendered only when `availability` is present in the Gemini JSON. The program does not invent a status.
- **Contact icons:** generic inline SVG line icons are used instead of brand logos.
- **No framework/build step:** HTML, CSS and vanilla JavaScript only.

## Empty-section behavior

The renderer conditionally creates sections only when their corresponding data exists:

- Profile → summary or skills
- Experience → experience entries
- Projects → project entries
- Education → education entries
- Achievements → achievement entries
- Contact → at least one contact value

The hero always exists because the bootcamp requires a portfolio identity, but its headline and availability badge remain empty when those source fields are absent.

## Mandatory testing matrix

| Test case | Expected behavior | Result / evidence |
|---|---|---|
| Missing `resume.txt` | Show clear error and stop safely | Run after temporarily renaming the file |
| Empty or very short resume | Reject input with useful message | Run with an empty/short file |
| Valid resume | Generate `portfolio.html` successfully | `python main.py` with valid key |
| Resume with missing sections | Generate available sections without inventing information | Use a minimal resume containing only identity/contact |
| Missing API key | Show configuration error | Remove `GEMINI_API_KEY` from `.env` |
| API failure | Handle failure without crashing | Use an invalid/unavailable model or temporarily disable network |
| Invalid JSON response | Show clear error and stop safely | Unit-test `parse_json_safely()` with malformed JSON |
| Mock renderer | Generate a complete local page without API | `python main.py --mock` |
| Theme switcher | All four themes preview without reload | Click each theme button |
| Project filter | Only matching project cards remain visible | Click each generated technology filter |
| Empty-section theme test | No empty headings/gaps across all themes | Use `--mock`, then test a sparse fixture if needed |
| Optional photo | Uses `photo.jpg` when present; CSS art when absent | Test both states |

Before submission, record the actual observed result in the final column and keep screenshots in the repository as required by the brief.

## Responsible AI and privacy

Do not use passwords, government identification numbers, financial details or other highly sensitive information in test resumes. Never upload the real API key to GitHub or screenshots. Do not move the Gemini call into browser-side JavaScript. Check every generated skill, project, date, company, achievement and link against the source resume.

## Limitations

- Gemini can still misunderstand ambiguous resume wording or return a plausible but unsupported rewrite. Structured output improves shape, not truthfulness.
- Theme inference is keyword-based and intentionally simple.
- A plain-text resume cannot provide reliable visual identity, so the no-photo hero uses generated CSS art rather than real portfolio imagery.
- External links are not verified by the generator; they are only safely escaped and inserted when present in the source data.
- The page uses a Google Fonts `@import`; if the browser is offline, the system falls back to local serif/sans/mono stacks.
- The generated portfolio is a static HTML file and has no server-side backend.
